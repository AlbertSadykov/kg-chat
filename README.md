# Кезик — анонимный чат Кыргызстана, 18+

Веб-приложение для общения со случайным собеседником один на один. Пользователь заполняет анонимную анкету, выбирает фильтры и начинает поиск. Обязательная регистрация с почтой и паролем не нужна.

Текущий комплект включает восстановление анкеты, блог с редактором, миничат на публичных страницах и Web Push. Последнее подготовленное обновление — 1.3. Дополнительные ручные изменения дизайна и логики на рабочем сайте могут отличаться от этого комплекта.

- Сайт: https://chatkg.tw1.ru
- Репозиторий: https://github.com/AlbertSadykov/kg-chat
- Ветка: `main`
- Папка сайта в панели хостинга: `chat/public_html`
- Деплой: GitHub Actions → FTP, с ручным запуском.

## Быстрый запуск обновления

Откройте терминал в локальной папке проекта:

```bash
git status
git add .
git commit -m "Описание изменений"
git push origin main
gh workflow run deploy.yml --ref main -f mode=push
```

Перед `git add .` проверьте список файлов. Для небольшого изменения можно добавить только нужный файл, например `git add app/Views/home.php`.

Проверка результата:

```bash
gh run list --workflow deploy.yml --limit 3
gh run watch
```

Во второй команде выберите нужный запуск. Дождитесь успешного завершения и проверьте сайт. Отправка кода в GitHub сама по себе сейчас не запускает деплой.

## Стек и требования

- PHP 7.4–8.3; без фреймворка и Composer на сервере.
- MySQL 5.7+/8.0 или MariaDB 10.3+, InnoDB, utf8mb4; запросы через PDO.
- Расширения `pdo_mysql`, `mbstring`, `json`, `openssl`, PHP sessions.
- Для загрузки изображений блога — `fileinfo`, доступная функция `getimagesize` и разрешённые загрузки PHP.
- Для Web Push — `openssl_pkey_derive` и исходящий HTTPS через cURL либо `allow_url_fopen`.
- Apache 2.4, `mod_rewrite`, разрешённые `.htaccess`; для nginx требуется отдельная маршрутизация.
- PHP должен иметь доступ на запись в `config/` при установке и в `storage/` при работе.
- HTTPS для публичного запуска и браузерных Push-уведомлений.

Фронтенд: обычные HTML, CSS и JavaScript без сборки. Редактор блога Quill хранится локально вместе с лицензией. Node.js, WebSocket-сервер и обязательный cron на хостинге не нужны. Инструменты GitHub Actions устанавливаются на временном runner GitHub, а не на хостинге.

## Возможности

### Пользовательская часть

- Анкета: ник, пол, возраст и город Кыргызстана.
- Обязательные подтверждение 18+ и согласие с правилами; сервер не допускает возраст ниже 18.
- Поиск по городу, полу и диапазону возраста, очередь и расширение фильтров.
- Атомарное сопряжение через транзакцию и блокировки БД.
- Сообщения и эмодзи, индикатор набора, доставка и прочтение.
- Ограничение длины, антифлуд, локальная капча при подозрительной активности.
- Следующий собеседник, завершение разговора и жалобы.
- Восстановление анкеты через защищённую cookie; действующий чат сохраняется при переходах в рамках таймаутов сайта.
- Русский и кыргызский интерфейс, тёмная и светлая темы.

Подтверждение возраста является заявлением пользователя, а не проверкой документов.

### Блог

- Список записей `/blog`, отдельные страницы публикаций и карточки на главной.
- Раздел `/admin/blog` для суперадминистратора.
- Локальный WYSIWYG-редактор Quill, обложка и изображения, черновики и публикация.
- Изображения находятся в `storage/blog/` и выдаются через приложение.
- HTML записи очищается на сервере; произвольные скрипты редактор не публикует.

### Миничат и уведомления

- На правилах, в блоге и других публичных страницах появляется миничат при действующем разговоре или поиске.
- Окно можно свернуть, увидеть счётчик новых сообщений, ответить и перейти в полный чат.
- На главной остаётся обычный полный чат; в админке миничат не подключается.
- Колокольчик в меню включает или отключает уведомления текущего браузера.
- Системное разрешение запрашивается после нажатия пользователя.
- Web Push отправляется при новом сообщении; в уведомлении нет текста переписки или анкеты собеседника.
- Push при открытом читаемом чате отображается тихо. Уведомление о найденном собеседнике формируется на открытой странице во время поиска.
- Worker не кеширует страницы, переписку или CSRF-токены.

Если обновление 1.3 загружено, но миничат не появляется, в `app/Views/header.php` перед `</head>` должен быть один вызов:

```php
<?php require ROOT . '/app/Views/chat-presence-head.php'; ?>
```

Проверьте, что `/chat-sw.js` возвращает JavaScript. Таблица подписок и VAPID-ключи создаются при первой подготовке Push-подписки; для этого пользователю БД требуется право CREATE.

На iPhone/iPad Web Push требует поддерживаемую версию ОС (начиная с 16.4), добавление веб-приложения на экран «Домой» и разрешение пользователя. На других платформах поддержка зависит от браузера и ОС. Миничат работает без разрешения Push.

### Админка

- Отдельный вход `/admin`, роли суперадминистратора и модератора, CSRF и ограничение попыток входа.
- Опциональный TOTP, управление администраторами и аудит действий.
- Дашборд, анонимные анкеты, активные и завершённые чаты.
- Жалобы и просмотр переписки только в рамках жалобы, предупреждения и баны.
- Города, стоп-слова, фильтры сообщений, настройки сайта, правил и хранения.
- SQL-экспорт БД и очистка устаревших данных.

## Первая установка на shared-хостинг

Эта инструкция нужна для нового сайта. На уже работающем сайте установщик повторно не запускается.

1. Создайте БД и пользователя в панели хостинга. Разрешите создание таблиц на этапе установки.
2. Загрузите содержимое папки проекта, сохранив все `.htaccess`.
3. Предпочтительно направить document root на `public/`, оставив `app/`, `config/`, `storage/` и `install/` вне публичной папки.
4. Если document root менять нельзя, как на текущем сайте, содержимое проекта размещается в `chat/public_html`. Корневая `.htaccess` перенаправляет запросы в `public/index.php` и закрывает внутренние папки.
5. Настройте запись PHP в `config/` и `storage/`. Обычно файлы имеют права 644, папки 755; необходимые права записи зависят от пользователя PHP на хостинге.
6. Откройте `/setup` и пройдите мастер. Это основной адрес установщика; в текущем роутере есть также алиас `/install`, но физическая закрытая папка может мешать его открытию на некоторых конфигурациях.
7. Укажите фактический HTTPS-адрес без `/public` и без завершающего слеша, данные БД и суперадминистратора.
8. После установки сохраните `storage/installed.lock` и удалите физическую папку `install/`. Если нужны исходники установщика для будущей новой установки, храните их отдельно.
9. В админке заполните данные оператора, поддержку, правила, лимиты и сроки хранения.
10. Проверьте вход, подбор, сообщения и жалобы в двух разных браузерах или профилях. Две вкладки одного профиля — один участник.

Для новой базы исходная схема находится в `install/install.sql`. Схемы блога и Push находятся отдельно и устанавливаются соответствующими модулями. Нельзя импортировать исходный install.sql поверх рабочей БД в качестве обновления.

## Маршрутизация и .htaccess

На текущем сайте проект лежит в корне публичной папки. Поэтому нужны и корневая `.htaccess`, и файл `public/.htaccess`. Не переносите папки при настройке деплоя.

На чистом nginx `.htaccess` не выполняется. Используйте document root на `public/` и настройте через панель или поддержку:

```nginx
location / {
    try_files $uri $uri/ /index.php?$query_string;
}
```

Если хостинг запрещает `Options`, согласуйте отключение листинга и корректировку директив с провайдером. Запреты прямого доступа к внутренним папкам должны сохраняться.

Если TLS завершается на доверенном прокси и PHP не видит HTTPS, настройка `'https' => true` в конфиге включает Secure cookie. Приложение не должно доверять произвольным прокси-заголовкам клиента.

## Деплой через GitHub Actions

### Текущая схема

Код редактируется локально, отправляется в `main`, затем вручную запускается workflow `deploy.yml`. GitHub скачивает репозиторий и через git-ftp загружает файлы на FTP. На сервере не нужны SSH или Git.

Первый `init` уже выполнен. Для обычных обновлений выбирайте `push`.

| Режим | Поведение |
| --- | --- |
| `init` | Загрузка всех отслеживаемых файлов, кроме исключённых, и запись текущего коммита |
| `push` | Загрузка новых и изменённых файлов относительно сохранённого коммита; удаление удалённых отслеживаемых файлов |

На сервере состояние хранится в `.git-ftp.log`. Сохраняйте этот файл. FTP-деплой не является атомарным: во время загрузки могут одновременно находиться старые и новые версии файлов. Существенные изменения выполняйте в режиме обслуживания.

### Доступы

GitHub → репозиторий → Settings → Secrets and variables → Actions:

| Secret | Значение |
| --- | --- |
| `FTP_URL` | Полный FTP-адрес с путём к проекту |
| `FTP_USERNAME` | FTP-логин |
| `FTP_PASSWORD` | FTP-пароль |

Пример URL: `ftp://FTP-СЕРВЕР/chat/public_html/`. Это шаблон: адрес и путь берутся из фактического подключения. Путь панели хостинга и путь внутри FTP-аккаунта могут отличаться. Для аккаунта с корнем непосредственно в папке сайта используется `/`.

Если провайдер предоставляет FTPS, можно использовать поддерживаемый git-ftp протокол и соответствующий порт: явный TLS — `ftpes://`, неявный — `ftps://`. Проверку сертификата не отключайте для обычного рабочего подключения.

Пароль не записывается в README или workflow. В текущей совместимой команде используется `--passwd "$FTP_PASSWORD"`; `--password-command` оказался недоступен в установленной версии git-ftp.

### Через браузер

1. Откройте верхнюю вкладку Actions репозитория, а не Settings → Actions.
2. Выберите Deploy website → Run workflow.
3. Выберите ветку `main` и режим `push`.
4. Дождитесь зелёной галочки и проверьте сайт.

### Через терминал VS Code

Один раз установите GitHub CLI в PowerShell:

```powershell
winget install --id GitHub.cli --exact
```

Перезапустите терминал, затем выполните:

```bash
gh auth login
```

Выберите GitHub.com, авторизацию через браузер и аккаунт с доступом к репозиторию. После этого используйте команды из раздела «Быстрый запуск обновления».

Журнал конкретного запуска:

```bash

```

Замените `ID_ЗАПУСКА` числовым ID из списка. `Queued` означает ожидание runner, `In progress` — выполнение. При ошибке откройте этап Deploy. После исправления workflow запустите новую задачу: повтор старого запуска использует старую версию файлов.

### Какие файлы передавать

`.gitignore` управляет добавлением в Git, `.git-ftp-ignore` — передачей на сервер. Это разные файлы; добавление правила не удаляет уже сохранённые данные из истории Git.

Для деплоя только кода рекомендуемый `.git-ftp-ignore`:

```text
config/*
storage/*
install/*
tests/*
uploads/*
public/uploads/*
.github/*
.gitignore
.git-ftp-ignore
README.md
SOURCE.md
*.zip
*.tar.gz
*.log
*.lock
```

git-ftp использует glob-шаблоны, а не регулярные выражения: `storage/*`, не `^storage/`.

В первом фактическом деплое storage, бэкапы и сессии передавались вместе с кодом. Если оставляете такой режим, учитывайте: повторная загрузка локальной сессии может заменить её состояние на сервере; удаление отслеживаемого файла из Git может удалить его при следующем `push`; копия папки не является актуальным резервным копированием работающего сайта. Для частичного обновления кода эти папки лучше исключить. Изменения исключений — отдельная настройка; этот README сам их не применяет.

При настройке исключений не удаляйте рабочие config/storage на хостинге. Если конфиг попадал в репозиторий, приватность репозитория и история коммитов имеют значение. Секрет сайта нельзя без подготовки менять: он используется для HMAC, восстановления анкеты и шифрования Push-подписок.

### Что деплой не обновляет

FTP переносит файлы. Он не переносит текущие данные MySQL и не выполняет SQL-миграции. Статьи, жалобы, настройки и анкеты находятся в БД.

Уже установленный сайт не обновляется повторным запуском `/setup`. Изменения схемы выполняются по инструкции конкретного обновления. Блог и Push имеют собственные предусмотренные процедуры подготовки таблиц.

После подключения GitHub локальный проект становится источником кода. Правку, сделанную прямо на хостинге, сначала перенесите локально и закоммитьте — иначе дальнейший деплой может её перезаписать.

## Резервные копии и откат

Перед существенным обновлением сохраните:

1. SQL-копию БД из админки или панели.
2. `config/config.php` с текущим секретом.
3. Файлы сайта и загруженные изображения из `storage/blog/`.

SQL содержит данные и настройки, но не заменяет конфиг или файлы изображений. Держите резервную копию вне единственной рабочей папки сайта. Откат кода через Git не откатывает БД.

Для отмены отдельного коммита можно выполнить `git revert ХЕШ_КОММИТА`, затем отправить получившийся коммит и запустить `push`. Если менялась структура БД, сначала подготовьте совместимый откат схемы и данных.

Восстановление SQL лучше сначала проверять в отдельной БД. Для прежних HMAC и зашифрованных Push-данных нужен тот же secret из исходного config.php.

## Реалтайм и нагрузка

По умолчанию `/api/state` вызывается коротким polling раз в 3 секунды. Это освобождает PHP-процесс между запросами. SSE не используется; опциональный long-poll может ждать до 20 секунд, но удерживает PHP worker.

В настройках задаются транспорт и интервалы. Для обычного shared оставляйте polling. При N=30 посетителях и интервале 3 секунды получается около 10 запросов состояния в секунду, плюс отправка сообщений и остальные действия. При N=100 — около 33 запросов состояния в секунду.

Начальный ориентир 10–30 одновременно активных пользователей — предположение для планирования, не измеренный предел текущего тарифа. Реальную вместимость определяют замеры CPU, MySQL, PHP workers, задержек и ошибок. Поиск сериализуется общим mutex и не рассчитан на тысячи одновременных участников.

Миничат использует короткий polling и синхронизацию вкладок. На главной модуль не добавляет второй постоянный цикл запросов. Без поддержки межвкладочной синхронизации запросов может стать больше.

Браузер способен заморозить фоновую страницу и остановить heartbeat. Push не отменяет таймаут завершения чата. Исходящая доставка Push выполняется после сохранения сообщения с короткими сетевыми таймаутами и может добавить задержку к ответу отправителю. При ошибке сообщение сохраняется, но уведомление может не прийти. Обязательной очереди повторной доставки и cron нет.

## Данные, модерация и очистка

- Собеседнику показываются только ник, пол, возраст и город.
- Приложение хранит HMAC IP, а не сырой IP. Серверные журналы провайдера — отдельный источник данных.
- Браузерный идентификатор является случайным ID, а не сбором аппаратного fingerprint.
- Жалоба хранит отдельный снимок переписки; его срок может отличаться от срока архива сообщений.
- Подозрение на несовершеннолетнего получает приоритет и временную изоляцию; окончательное решение принимает модератор.
- Отключение архива сохраняет кратковременное хранение для доставки сообщений.
- Очистка работает небольшими порциями на запросах. Без посещений физическое удаление откладывается до следующего запуска очистки.
- Настройки и номера уведомлений могут храниться в браузере; текст переписки модуль миничата в localStorage/IndexedDB не сохраняет.

Сроки, лимиты и включение архива меняются в админке. Текущие значения рабочего сайта нужно смотреть там, а не считать равными значениям по умолчанию в коде.

Страница политики — шаблон, который нужно адаптировать к оператору, месту хостинга, контактам и фактической работе с данными, включая браузерную службу уведомлений. README не является юридическим заключением.

## Проверка после обновления

- Главная, блог, правила и админка открываются без ошибок.
- Анкета восстанавливается при возврате на главную.
- Два разных браузера находят друг друга и обмениваются сообщениями.
- Фильтры, следующий собеседник, завершение и жалоба работают.
- Блог сохраняет черновик, публикует запись и отображает изображения.
- Миничат работает на другой публичной странице и переходит в полный чат.
- Колокольчик запрашивает разрешение; реальное уведомление проверено на HTTPS в поддерживаемом браузере.
- При обновлении JS/CSS выполнена принудительная перезагрузка страницы.

Локально проверялись PHP/API, БД, криптография Push и JS через DOM/worker-тесты. Эти проверки не гарантируют доставку через службы браузеров на конкретном телефоне. Матрица всех версий PHP/MySQL и нагрузочный тест рабочего хостинга не выполнялись.

## Известные ограничения

Нет пользовательских аккаунтов с паролем, голосовых сообщений, видеозвонков, списка друзей и поиска по интересам. Загрузка картинок есть у администраторов блога, но не в анонимной переписке. Нет проверки возраста по документам и гарантированного определения одного физического человека.

Доставка и прочтение — технические подтверждения клиента, а не доказательство внимания человека. Капча и фильтры не распознают все обходы. Баны по общему IP могут затронуть других пользователей. Push зависит от разрешения, браузера, ОС, сети и доступности исходящих HTTPS-запросов.

`SOURCE.md`, если сохранён на сайте, может содержать старый снимок исходников. Рабочий код — реальные файлы проекта и актуальные коммиты Git, а не этот вспомогательный документ.
